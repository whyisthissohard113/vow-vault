## Completed

### Core Build Engine (`src/server/services/build-engine.ts`)
- **15-step pipeline** with proper ordering: validate → verify payment → verify entitlement → create vault → apply template → public URL → configure expiry → create gallery → create slideshow (Gold/Platinum) → create flipbook (Platinum) → generate QR → generate QR card (Platinum) → publish vault → queue email → audit event
- **Idempotent job enqueueing**: Uses `idempotency_key` (unique) + `(wedding_id, version)` (unique) to prevent duplicate production vaults
- **Retryable with exponential backoff**: Max 3 attempts, 1s/2s/4s delays
- **Observable**: All steps tracked in `build_job_steps` table with status, timing, error messages
- **Non-retryable errors**: Validation errors, missing payment, missing entitlement fail immediately without retry
- **Entitlement-driven**: Slideshow (Gold/Platinum), Flipbook (Platinum), QR Card (Platinum) only created when entitled
- **No duplicate vaults**: Rebuilds with incremented version reuse existing vault

### Background Worker (`src/server/services/build-worker.ts`)
- Polls for pending jobs every 5 seconds
- Max 3 concurrent jobs
- Recovers stale jobs (stuck in "processing" > 5 min) on startup
- Graceful shutdown handling (SIGTERM/SIGINT)

### API Routes
- `POST /api/build` - Enqueue build with idempotency key
- `GET /api/build/[id]` - Get build status with step details
- `POST /api/build/[id]/retry` - Retry failed build
- All routes protected with auth + tenant + permission guards

### Auth Middleware Updates (`src/server/middleware/auth.ts`)
- `RouteParams` type for type-safe route parameters
- `AuthenticatedHandler` / `RawHandler` types with proper context passing
- `withAuth` / `withTenant` pass `params` through the chain
